Support & troubleshooting

How I work through technical problems.

I try to make troubleshooting repeatable: understand the impact, isolate what changed, test the safest explanation first, verify the result, then document it clearly.

Real support example

Repeated application crashes across multiple staff devices

When several staff members began seeing the same application crash, I compared affected and unaffected devices instead of treating each ticket as an isolated problem.

  • Checked what the affected systems had in common.
  • Compared recent changes and identified a compatibility problem tied to an update.
  • Used a temporary rollback so staff could continue working while the underlying issue was addressed.
  • Documented the steps so the same symptoms could be recognized faster if they appeared again.

What this shows: pattern recognition, change based troubleshooting, clear documentation, and focusing on business impact.

Microsoft 365 lab

Shared mailbox permissions and mail flow

In my Microsoft 365 lab, I configured a Legal Support shared mailbox and distribution list, then tested access and delivery from both user accounts.

  • Configured Send on Behalf permissions.
  • Verified which actions worked from each user account.
  • Used Message Trace to follow mail flow and confirm the final configuration.

What this shows: I do not stop at changing a setting. I test from the user side and use available logs or admin tools to confirm the result.

Account access

User cannot sign in

For an account access issue, I first narrow down whether the cause is the account, the password, the device, or connectivity.

  • Confirm the exact error and whether the issue affects one user or multiple users.
  • Check for lockout, disabled status, expired password, permissions, and group access.
  • Verify VPN or network access when the user is remote.
  • Reset or unlock the account when authorized, retest with the user, then record the outcome in the ticket.
Connectivity

Network or VPN connection issue

I separate basic connectivity from VPN specific problems so I do not spend time troubleshooting the wrong layer.

  • Verify the local internet connection and adapter status first.
  • Use tools such as ipconfig and ping to check addressing, gateway reachability, and name resolution.
  • Review the exact VPN error, credentials, password status, time settings, and client configuration.
  • Escalate with the error, tests already completed, and useful logs when the issue requires network administration.
